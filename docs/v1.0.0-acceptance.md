# 1.0.0 驗收與發布狀態

日期：2026-10-25。

## 範圍

1.0.0 是 major 版本，因為 Protocol v4 是破壞性變更：Daemon 只接受 v4 Agent。0.11.1、0.12 都沒有單獨發佈，命令延遲規劃 P0–P3 全部收進這一版。

- PR #190（P0）：線上 `td` 不再匯入 Daemon 伺服器套件，並重用 HTTP 連線；`td-daemon` 與 `td-agent` 改以 onedir 發佈。驗收見 [p0-latency-acceptance.md](p0-latency-acceptance.md)。
- PR #197（P1）：已授權的 Command 在同一個 frame 內執行，`td` 改用長輪詢。驗收見 [p1-latency-acceptance.md](p1-latency-acceptance.md)。
- PR #208（P2a）：`td` 換成 Rust 寫的原生 `td.exe`。驗收見 [p2a-latency-acceptance.md](p2a-latency-acceptance.md)。
- PR #213（P2b）：Protocol v4，Agent 在 `request_dispatch` 的 callback 內登記並執行。驗收見 [p2b-latency-acceptance.md](p2b-latency-acceptance.md)。
- PR #218（P3）：`plan.execute` 與 `commands execute --frame-batch`。驗收見 [p3-frame-batch-acceptance.md](p3-frame-batch-acceptance.md)。
- `td-agent upgrade-project` 白名單新增精確 canonical 0.11.0 Agent。
  - 五個 hash 取自已安裝的官方 0.11.0 `td-agent.tox`（SHA-256 `06919e5e2c7338aa9f1603821026a5af477ed2314e6a7c3a65707d9b9e7ec4ee`，與 v0.11.0 安裝 manifest 的 `artifact_sha256` 相同）：以 `VendorTools.expand` 展開後，由 `script_hashes` 算出。
  - 0.11.0 的 `socket_callbacks` 與 `heartbeat_execute` 也和 0.6.0 不同，所以五個 hash 全部明寫。
- 離線升級接受白名單舊版的 Protocol 3 事件表。Protocol v4 從 SocketIO DAT 的事件表移除了 `request_execute`，原本的結構檢查要求來源與目標的表完全相同，所以舊版 Agent 都升不上 1.0.0。來源是已核准的舊版時，現在也接受精確的 Protocol 3 事件表（SHA-256 `3808f124…`）。同版重跑仍要求完全相同。這個問題在下面的離線升級中第一次執行時被擋下，修正後重跑。
- `uv.lock` 與 `Cargo.lock` 只改本專案版本字串，`LICENSES/inventory.json` 只更新兩個 lock digest；`scripts/check_licenses.py` 驗證 307 份授權文件。

## 隔離 locked 驗收（candidate）

一次性專案沿用 0.11.0 的作法：一個 Execute DAT 依專案名稱執行對應步驟，以 `toecollapse` 收合。啟動時 `LOCALAPPDATA` 指向暫存目錄，Agent 找不到 `auth.token`，停在 `waiting_for_daemon`。使用者的 Daemon 全程未觸碰；每一步結束時機器上都沒有 TouchDesigner 程序。

- [build.json](evidence/v100/build.json)：PID 28724 以 `agent/build_td.py` 從 release commit `3fedf90` 的 source 建置 candidate（revision `3627ba33601d5cb32ed85dbf5faf90a1106a67a81a5883f6bae87e8b421a99e3`），SHA-256 `0e34f06a18afbf95d10ba8e1c36f469300b57aef4b1b1186efcb36956ab24392`。之後的升級修正只改 `src/td_cli`，Agent source 不變。
- [verification.json](evidence/v100/verification.json)：PID 25428 以 `loadTox` 載入 candidate。Agent 為 1.0.0，capabilities 含 `plan.execute`、`parameters.menu.set` 與 `project.snapshot:options`，socket 未啟用。3 項 menu 以 `preserve=index` 改名後讀回一致，`validated=true`。
- [frame-batch-candidate.json](evidence/v100/frame-batch-candidate.json)：以 `tools/locked_frame_batch_acceptance.py --artifact` 走真實 Daemon transport（隔離 port 19982）與 SocketIO DAT，在 candidate 上重跑 P3 的 Frame Batch 驗收（TD PID 27456，exit 0，Daemon thread 正常停止，Agent 1.0.0）。256 個 `ops.create` 加 256 個 `parameters.set`：逐一 8,644 ms、512 個 Request；`--frame-batch` 1,747 ms、47 個 Request。最慢一段 10.39 ms，低於 11.52 ms 的上限；兩種模式的 frame 間隔最大值都約 17.2 ms；兩邊讀回都是 256 個 Constant CHOP，值正確。第一次執行時 `--artifact` 給了相對路徑，TouchDesigner 載不到 Agent，改用絕對路徑後重跑。

## 離線升級、同版與冷開

執行前確認全機沒有 TouchDesigner 程序。

1. [source-0.11.0.json](evidence/v100/source-0.11.0.json)：PID 29044 載入官方 0.11.0 Agent（沒有 `plan.execute`）與 sentinel Constant CHOP（42），存成一次性的 `src0110.toe`，SHA-256 `b3a0c6aa583d177321eeb502481583649d5ea778736e34a63ff472eb64fd3215`。
2. [upgrade.json](evidence/v100/upgrade.json)：

   ```powershell
   uv run td-agent upgrade-project .codex\release100\src0110.toe --artifact .codex\release100\candidate\td-agent.tox --manifest .codex\release100\candidate\td-agent.tox.manifest.json --tools-dir "C:\Program Files\Derivative\TouchDesigner\bin" --expected-sha256 b3a0c6aa583d177321eeb502481583649d5ea778736e34a63ff472eb64fd3215 --timeout 90
   ```

   `status` 為 `upgraded`，Agent 1.0.0，留下備份，新的 SHA-256 為 `e9ffe71e3ada3984e217a5d9e3b1522840f1f58c3b49a243c2dc6b248d2c76f2`。
3. [upgrade-rerun.json](evidence/v100/upgrade-rerun.json)：以升級後的 SHA-256 再執行一次，`status` 為 `unchanged`，檔案 bytes 不變。
4. [cold-0.11.0.json](evidence/v100/cold-0.11.0.json)：PID 29288 冷開升級後的專案。Agent 為 1.0.0，`Connectionstate` 為 `waiting_for_daemon`，socket 未啟用，capabilities 含 `plan.execute`；sentinel 仍為 42；menu 改名後讀回一致，`validated=true`。

## 限制

- 離線升級只實測 0.11.0 → 1.0.0。0.11.0 以前的白名單版本走同一條路徑，由 `tests/test_agent_upgrade.py` 涵蓋，沒有逐版實測。
- Snapshot 的 `accepted_at` 與 `execute_authorized_at` 在 v4 永遠是 null，仍保留在 schema 中，沒有移除。

## 發布 gate

合併後依 [release-operations.md](release-operations.md) 進行 develop → main promotion，在 exact main 上建置、驗證並 staging Agent，再執行 Publish Release。`release` environment 需要 tedliou 本人核准；核准前不宣稱已發布。
