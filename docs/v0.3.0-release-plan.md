# v0.3.0 Release plan

## Version decision

The production reliability redesign ships as `v0.3.0`. Published `v0.2.0`
assets and tags remain immutable. This is a pre-1.0 minor release because it
intentionally replaces Protocol v1 with Protocol v2 across the CLI, Daemon,
HTTP and Socket.IO surfaces; presenting that change as a patch would obscure
the compatibility boundary.

All three executables and the TouchDesigner Agent Component form one release.
Mixing v0.2 and v0.3 processes is unsupported: registration advertises only
Protocol v2 and fails closed rather than enabling a compatibility fallback.

## Release gates

- Version sources agree on `0.3.0`: package metadata, lockfile, Agent manifest,
  executable version output, archive names, installer metadata and tests.
- The full automated gate and independent Standards/Spec review for #83 and
  #90 remain green on the promoted commit.
- TouchDesigner 2025.32050 rebuilds the Agent artifact from the exact final
  source and repeats locked source, scheduler, auth, performance, crash replay
  and orderly reconnect acceptance.
- The Agent stage binds the artifact bytes, structural manifest, locked-runtime
  verification, exact source commit and Release Version before upload.
- Promotion to `main`, the protected release-environment approval, immutable
  tag creation, draft-first asset upload, remote digest verification and final
  publication are mandatory.

## Intentional limitations

- No Protocol v1 alias, alternate transport or fallback scheduler is shipped.
- Authorized mutations are never retried automatically; uncertain execution
  remains `unknown` until the matching retained outcome refines it.
- TouchDesigner Power Off remains unsupported.
- Windows executables remain unsigned; published SHA-256 checksums establish
  integrity but do not bypass PowerShell, SmartScreen or Defender policy.
