# Domain Docs

工程技能在探索程式碼前，應依下列規則取用領域文件。

## 探索前先讀

- 根目錄的 `CONTEXT.md`；或
- 若存在根目錄的 `CONTEXT-MAP.md`，依其指向讀取與主題相關的 `CONTEXT.md`；
- `docs/adr/` 中與工作範圍相關的 ADR。

若上述檔案不存在，請直接繼續，不必特別提出。

## 檔案結構

本 repo 採單一領域脈絡：

```
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

`/domain-modeling` 會在真正需要釐清術語或決策時，才建立這些文件。

## 使用詞彙表用語

在 issue 標題、重構提案、假設與測試名稱中，應使用 `CONTEXT.md` 所定義的術語，避免改用其明確排除的同義詞。若概念尚未被定義，應重新評估用語或記錄為 `/domain-modeling` 的待釐清項目。

## 標示 ADR 衝突

若產出內容與既有 ADR 衝突，應明確說明衝突，而非默默覆寫。
